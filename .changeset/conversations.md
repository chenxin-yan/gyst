Discuss code and notes with the agent. In the browser viewer the human comments on any captured range (`c`, or the gutter `+` in Mouse mode), replies to a note or thread (`r`), resolves or reopens a thread (`x`), steps between open threads (`]t` / `[t`) and lists every conversation, resolved ones included (`C`). Each human message is a Question or a Change request and stays Pending, editable and deletable, until the agent retrieves it. `gyst session threads --session <id> --pending|--open --request-id <id>` is that retrieval: one atomic step that returns each thread's history, original code and reply wording with Viewed progress and the open-thread count, freezes exactly the unread messages it returns and answers a retry of the same request id with the same bundle. Agents answer with `thread.reply` ops in `gyst session apply`, atomically with guidance changes; they cannot start, resolve or reopen threads or write as the human. `status` reports thread counts only, never a Pending body, and a PR stack's layers show their unresolved threads. Refresh moves a code thread only when every line it targets maps unchanged, keeping the rest on their original captured code, and conversations and drafts keep the snapshots they refer to readable. Sessions saved by earlier versions are not migrated.
