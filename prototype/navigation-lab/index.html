Measurements, engine versions and limits

Startup means LSP initialize + document notifications, not guaranteed full indexing. Query timings are real wall time; initial queries may include project loading. Engines are queried sequentially. Tiny fixture timings are not repository-scale benchmarks. Editing restarts the live server rather than measuring incremental updates.

The SCIP reader matches exact symbols, including file-scoped local symbols. It does not yet expand implementation/inheritance relationships or fetch external packages. The indexer uses a different TypeScript version from the native LSP; differences can reflect compiler versions as well as backend design. Try references on applyDiscount in checkout.ts versus discount in preview.js: alias queries can have a narrower scope in native TypeScript. Results are deliberately not normalized.

Scratch data only. Actual TypeScript LSP requests and actual SCIP artifacts; no fake results. Source browsing is simplified full-file context, not a production diff renderer. All projects are scratch data; reset or stop the server to discard edits. The protocol trace and process handling are intentionally limited to this experiment.
